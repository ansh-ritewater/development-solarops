# Full Platform Audit — Index

**Conducted 19-22 August 2026.** Seven documents, one connected
investigation. Nothing in any of them has been fixed — this was
deliberately audit-first, fix-later, at Ansh's explicit direction.
This index exists as the one place to see everything at a glance
before deciding what to actually work on.

## The seven documents, in the order they were produced

1. **`FILTER_AUDIT.md`** — every real Tasks-page filter combination,
   classified. Found 1 genuine regression (Search silently ignored
   when combined with State/Lead Source on 17 tabs).
2. **`FEATURE_AUDIT.md`** — complete route/role map, every admin
   action across 5 pages. Found the systemic pattern: admin actions
   are UI-hidden, almost never code-enforced.
3. **`BACKEND_ROADMAP_AUDIT.md`** — the 6-item backend-dependent list
   reconfirmed unchanged; the role-check gap precisely sized (29
   functions, 4 distinct fix categories); found the `UpdateTaskDrawer`
   structural gap (field-level, not just role-level).
4. **`PERFORMANCE_AUDIT.md`** — fresh bundle measurements; one alarming
   number (vendor-firebase 5x growth) resolved as a measurement error,
   not real; found the genuinely important one — Algolia's free tier
   ceiling sits at HALF the platform's stated 1-lakh-task target.
5. **`SECURITY_AUDIT.md`** — full rules re-read; found a new
   `stages`-subcollection lingering-access issue; the single most
   important finding of the whole audit: unvalidated field-role edits
   can propagate automatically into platform-wide search results.
6. **`PRODUCT_GAPS_AUDIT.md`** — 4 externally-suggested improvements,
   each verified against real code (one premise was wrong, one
   reprioritized as more urgent than it looked, one mostly already
   solved); plus the lifecycle-duration and Excel/Reports
   completeness gaps.
7. **`STAGE_WORKFLOW_AUDIT.md`** — Field Review/Proposal/Backend's
   real workflows; found 2 more instances of the project's most-
   repeated bug pattern (duplicate logic that could silently drift),
   bringing the running total to 6 confirmed instances across the
   whole project's history (later 7 — see below; `toAlgoliaRecord`
   was found independently, outside this audit series).

## Everything found, grouped by what it actually needs — not by
which document it came from

**Small, contained, no backend needed, could be done quickly whenever
picked up:**
- Search+State/Lead-Source regression (`FILTER_AUDIT.md` #10)
- The 7 duplicate-logic-drift instances (Pipeline Counts, isOverdue,
  Conversion Date, Sales Closed mapper, Field Review next-stage,
  Proposal revision numbering, `toAlgoliaRecord`)
  — `toAlgoliaRecord` is duplicated across
  `functions/src/syncToAlgolia.ts` and
  `functions/scripts/backfillAlgolia.ts`, kept in sync only by a code
  comment referencing the other file, with no shared source of truth.
  Any field mapping change must be applied to both, identically, or
  the live sync and the backfill tool will silently diverge.
- 22 of 29 missing role checks (`BACKEND_ROADMAP_AUDIT.md`) — simple,
  proven one-line pattern
- Payment-type-can-be-reset and Convert-not-reverified integrity gaps
  (`STAGE_WORKFLOW_AUDIT.md`)
- Employee Name / Lead Generated By Note → dropdown (`PRODUCT_GAPS_AUDIT.md`
  Gap 3), once a small admin-managed employee list exists

**Needs a real design decision before any code, still no backend:**
- `UpdateTaskDrawer`'s field-level write gap (needs a structural
  decision — split the write path, or field-level rules)
- 5 of 29 role-check fixes that also need `firestore.rules` tightened
- Drop-reason capture on Admin Override (Gap 2) — needs the actual
  reason list designed, not just a code change
- Excel export consistency + completeness (correction status,
  remarks, per-stage duration, the two disagreeing Conversion Dates)

**Genuinely needs backend infrastructure (already tracked, unchanged):**
- App Check, `errorLogs` rate-limiting, custom auth claims, counter
  centralization, push notifications — the original 6-item list
- Lead-clock escalation, Phase B (Gap 1) — rides on the same push-
  notification infrastructure already listed above, not a new need

**Bigger, deliberately not scoped in detail yet:**
- Lifecycle-duration tracking (Gap 5) — real, buildable, but a genuine
  feature, not a quick fix; the 50-entry `stageHistory` cap limits how
  far back it could ever reach
- Reports page redesign — real inventory now documented; whether it's
  worth rebuilding is Ansh's own judgment call
- `templateVersion` migration — unrelated to backend, already flagged
  "don't rush" since before this audit began

**Confirmed fine, no action needed:**
- Cross-stage data flow (nothing lost or duplicated)
- Algolia/backend admin-SDK scope (all three scripts/functions
  properly bounded)
- Both Algolia API keys (verified against real Algolia documentation)
- Cloud Functions' own invocation limits (nowhere close to a real
  constraint)

## The one finding worth reading even if nothing else gets read

`SECURITY_AUDIT.md`'s cross-cutting finding: a field-role user's
unvalidated edit to their own assigned task (via the confirmed
`UpdateTaskDrawer` gap) doesn't stay contained — `syncTaskToAlgolia`'s
confirmed lack of any validation means fabricated data (a false
`saleClosed`, a tampered `state`) propagates automatically into
search results visible to every admin/view_only user. This is the one
place two separate audit passes combined to reveal something neither
showed alone.
